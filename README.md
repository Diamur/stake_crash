# MEP / GamePanel

Браузерный встраиваемый модуль и панель статистики для страниц казино-игр, в первую очередь для crash.

## Что это такое

MEP / GamePanel — это не отдельный сайт и не backend-сервис.

Это клиентский скрипт, который работает прямо внутри страницы игры, подключается к живым данным, встраивает боковую панель управления и помогает отслеживать статистику, серии, пороги, историю результатов и другие игровые показатели.

Проект предназначен для оперативного наблюдения за результатами и визуального анализа прямо в интерфейсе сайта.

## Что делает скрипт

Во время работы скрипт:

1. Перехватывает window.WebSocket.
2. Анализирует входящие сообщения игры.
3. Извлекает игровые данные и идентификаторы раундов.
4. Встраивает на страницу правую панель управления.
5. Следит за DOM-блоком с прошлыми результатами.
6. Поддерживает внутреннюю историю результатов.
7. Показывает статистику и серии.
8. Строит графики по последним значениям.
9. Показывает diff-график для сравнения >= 2 и < 2.
10. Загружает историю через интерфейс сайта.
11. Сохраняет настройки локально.
12. Может отправлять live-данные и настройки на backend endpoint.

## Возможности

### Живой перехват данных

Скрипт подключается к WebSocket-потоку страницы и извлекает игровые события без поломки нативной логики сайта.

### Встроенная правая панель

На страницу добавляется фиксированная панель с:
- заголовком
- счётчиком
- блоком статистики
- таблицей отслеживания
- diff-графиком
- основным графиком
- настройками

### Отслеживание результатов через DOM

Помимо WebSocket, скрипт отслеживает визуальный блок результатов на странице и использует его как источник актуальных значений.

### Загрузка истории

Можно открыть историю игры через интерфейс сайта, пройтись по страницам и импортировать прошлые результаты в локальное состояние панели.

### Таблица отслеживания порогов

Для каждого значения X можно отслеживать:
- цвет строки
- текущую серию "Подряд <= X"
- порог срабатывания
- звук при срабатывании

### Графики

Поддерживаются:
- график последних множителей
- diff-график
- сравнение количества значений >= 2 и < 2

### Звуковые уведомления

При совпадении условий могут проигрываться выбранные звуки.  
Есть режим приоритета при одновременном срабатывании нескольких строк.

### Настройки и синхронизация

Настройки можно:
- хранить локально
- загружать
- сохранять
- при необходимости синхронизировать с backend endpoint


## Горизонтальные уровни diff-графика (+ / -)

В блоке diff-графика есть два ручных параметра:

- `+` — уровень горизонтальной пунктирной линии в плюсовой зоне
- `-` — уровень горизонтальной пунктирной линии в минусовой зоне

Эти параметры нужны для визуальной разметки графика разниц.

### Как это работает

Diff-график строится относительно центральной оси `0`.

- значение из поля `+` рисует пунктирную горизонтальную линию выше центральной оси
- значение из поля `-` рисует пунктирную горизонтальную линию ниже центральной оси

Обе линии являются визуальными ориентирами и помогают быстро оценивать, насколько текущая разница отклоняется вверх или вниз.

### Особенности

- уровни задаются вручную пользователем
- используются целые неотрицательные значения
- значение `0` отключает соответствующую линию
- линии отрисовываются прямо внутри SVG diff-графика
- после изменения значения график должен сразу перерисоваться

### Пример

Если указать:

- `+ = 3`
- `- = 4`

то на diff-графике появятся:

- одна пунктирная линия на уровне `+3`
- одна пунктирная линия на уровне `-4`

### Где хранится

Параметры уровней сохраняются в состоянии панели:

- `MEP.State.diffPosLevel`
- `MEP.State.diffNegLevel`

При сохранении состояния панели эти значения должны восстанавливаться после перезагрузки страницы.

### Для чего это полезно

Функция помогает:

- визуально отмечать важные уровни отклонения
- быстрее анализировать зоны перекоса diff-графика
- сравнивать текущие движения с заранее выбранными контрольными уровнями
- видеть, когда график регулярно уходит выше или ниже ожидаемой амплитуды

### Важно

Если поля `+` и `-` есть в интерфейсе, но линии не появляются, сначала нужно проверить:

- обновляются ли `MEP.State.diffPosLevel` и `MEP.State.diffNegLevel`
- совпадают ли имена UI-ссылок между `mount()`, `bind()` и `apply`-логикой
- вызывается ли повторный `MEP.DiffGraph.render()`
- добавляются ли SVG-линии в `ui.diffSvg`

## Состояние проекта

Основное состояние хранится в объекте MEP.State.

Ключевые данные:
- список результатов
- параметры графика
- параметры diff-графика
- настройки отслеживания
- флаги загрузки истории
- настройки звуков
- выбранная игра
- поддержка текущего game slug

Важно:
- список результатов хранится в формате newest-first
- при загрузке истории live-трекер временно приостанавливается
- старые форматы настроек поддерживаются через миграцию

## Принципы разработки

При доработке проекта важно соблюдать следующие правила:

1. Делать точечные правки, а не глобальные переписывания.
2. Не ломать существующую архитектуру window.MEP.
3. Не удалять DOM-fallback только потому, что есть WebSocket.
4. Не удалять миграции старых форматов без полной замены всей совместимости.
5. Не переименовывать CSS-классы и публичные сущности без необходимости.
6. Не убирать существующие комментарии без прямого запроса.
7. Сначала сохранять рабочее поведение, потом улучшать структуру.
8. Не превращать проект в React/Vue-приложение без отдельной задачи.
